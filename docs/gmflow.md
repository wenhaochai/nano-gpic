# GMFlow：每一步输出速度的高斯混合

一句话结论（2026-11-05）：每个像素输出速度的 8 个高斯的混合（GMFlow），用 GM-ODE 采样，在 50 步时和点模型持平（FD −0.6% 和 +0.7%），在 8 步时比点模型最好的采样器低 6.0% 和 9.3%（C0/16 和 C0/8），但只有一个高斯、损失相同的对照已经拿到这个优势的约三分之二，混合自己多出的 2.3% 和 3.4% 没有达到 5% 的判定线。

## 1. 问题

点模型每一步输出一个速度。owner（2026-11-05）要每一步直接输出 v 的连续分布，不要离散的 v。

跳跃 + 速度（`jump_flow` 分支）失败的原因很可能是训练细节：同一份权重只用速度采样时 covered 0.066，只训练速度时 0.81 到 0.88。跳跃损失伤了共享主干。

GMFlow（Chen 等，ICML 2025）每个像素输出 v 的高斯混合，损失是负对数似然。K = 1 且方差固定时，它等于现在的 L2 损失。它只有一个损失，所以没有两个损失互相干扰的问题。

数学要点：每步从 p(v | x_t) 独立抽 v 时，每步的随机性和步长成正比，步数多时路径接近均值的 ODE。所以采样用 GM-SDE：先从混合分布抽 x̂，再按高斯桥走一步。

## 3. 相关工作的笔记

Sphere Encoder 2（arXiv 2610.02208，2026-10）：

1. 它也发现逐像素损失会平均所有可能的图。输入只剩噪声时，解码器输出类别的平均图。
2. 它不用分布头。它按噪声分两段：α < 70° 用逐像素损失，α > 70° 用冻结 ConvNeXt V2 特征上的分布匹配（DMD 式的两个在线 score 网络）、ConvNeXt logits 上的 LPIPS 和 DINOv3 一致性。
3. 可借鉴：(a) 分布损失只在高噪声段需要。GMFlow 的 NLL 自己会做到，所以记录一个诊断：每个 t 实际用到几个分量。(b) 在特征空间匹配分布，可作为能量分数头的后续方向。
4. 不直接用：它的训练损失用 DINOv3、ConvNeXt V2 和 Inception 特征，FD-lite 直接优化这些特征上的 FD；它的指标 FDr6 平均 6 个特征空间，其中有 DINOv2。论文没有讨论这个偏差。它匹配的是输出的整体分布，不是每一步的条件分布 p(x | x_t)。它没有报告训练算力的额外开销。
5. 如果以后做特征空间的分布匹配：特征网络不用 DINO，并且同时报告第二个指标。

## 4. 实现

分支 `gmflow`，worktree `gpic-wt/gmflow`。代码提交 ef1346e。完整的英文报告在 `docs/gmflow_impl_report_2026-11-05.md`。作业都写好了，都没有提交。

### 4.1 做了什么

1. 模型：`JiT_T2I` 增加选项 `gm_k`（K）。`gm_k = 0` 时就是官方点模型。
2. `gm_k > 0` 时，最后的 Linear 每个 token 输出 p² · K · 4 个数。p = 16。
3. unpatchify 之后，每个像素有 K 个 RGB 均值和 K 个 logit。均值是 x 预测。logit 在 K 这一维上做 log_softmax。
4. 方差：每个样本一个标量 log s_u，单位是速度。图像空间的标准差是 s_x = (1 − t) · s_u。
5. s_u 来自一个单独的 MLP：SiLU → Linear(640, 1024) → SiLU → Linear(1024, 1)。输入是时间步嵌入加上 caption 嵌入在真实 token 上的平均。输入不传梯度。
6. 初始化：最后的 Linear 用 Xavier 权重和 0 偏置，和 GMFlow 发布的模型相同。s-MLP 的最后一层是 0，所以开始时 s_u = 1。其他层和基线相同。
7. 损失：`GMFlowTrainer`，GMFlow 的 transition loss，λ = 0.5，乘 2。t 的分布和基线相同（logit-normal，−0.8，0.8）。损失在 fp32 里算，关掉 autocast。损失里没有 t_eps。
8. 输出模式：训练用完整的混合。默认模式输出混合均值 Σ A_k μ_k，所以官方 Euler 不用改就能跑（“均值 Euler”）。
9. 采样器：
   1. `GMSDESampler`：每个像素独立地从混合里抽 x̂，再走高斯桥的一步。最后一步返回抽到的 x̂。选项 `final_mean` 让最后一步用混合均值。
   2. `GMODESampler`：每次调用后做 n 个解析子步。50 次调用 n = 3，8 次调用 n = 16。
   3. 点模型（K = 0）上，`GMSDESampler` 把输出当作 K = 1、s = 0。这就是小方差的 DDPM。
   4. 都断言 CFG = 1.0。
10. 诊断：每 100 步记一次（只在写日志的步上算，不加前向，不加 host 同步）。内容是 NLL、平均 s_u、每个像素的有效分量数 exp(H(A))、K 个分量平均权重的最大值、按 σ 分 4 段的 s_u 和有效分量数、裁剪前的梯度范数。
11. 配置：`gmflow_train.yaml` 从 `energy_train.yaml` 复制而来，只改了头和训练器。优化器、学习率、batch、EMA、梯度裁剪、编译、数据、裁剪方式和种子都和 w1147 相同。caption dropout 是 0。

### 4.2 FLOPs 和步数

用 `FlopCounterMode` 测 d640 的前向，文本长度 8，方法和能量头相同（`tools/gmflow/test_gmflow.py` T9）。r 是增加的 FLOPs 除以 34.72 GFLOP。

| K | 增加的 MFLOP | r | STEPS | STEPS × (1 + r) |
|---|---:|---:|---:|---:|
| 8 | 2434.01 | 0.07010 | 62336 | 66706 |
| 1 | 85.20 | 0.00245 | 66560 | 66723 |

1. 实测的增加量和手算完全相等。手算是 2·256·640·(K·1024 − 768) 加上 s-MLP 的 2·(640·1024 + 1024)。
2. STEPS 是满足 STEPS × (1 + r) ≤ 66816 的最大的 128 的倍数。MS = STEPS / 4：K = 8 是 15584，K = 1 是 16640。
3. C0/16 的检查点：K = 8 是第 31168 步，K = 1 是第 33280 步。

### 4.3 测试（vis2 CPU，全部通过）

1. T1：K = 1、s_x ∝ (1 − t)、λ = 1 时，μ 上的梯度等于基线 v 损失梯度乘一个常数 C / c²。实测 6.122448，理论 6.122449。只比较 1 − t ≥ 0.05 的样本。
2. T2：写在 x 上和写在 v 上的 NLL 相差 C log σ，梯度相等，误差 9e-15。
3. T3：两段前向过程的蒙特卡洛（200 万个样本，4 组 σ）给出 c1、c2、c3，和公式一致。λ = 1 时 c = (0, 1, 0)，训练器的损失等于 x 混合下普通 NLL 的 2 倍。
4. T4：已知两峰后验的玩具问题上，从随机初始化做梯度下降，恢复了两个均值（误差 0.001）、两个权重（0.289 / 0.711，和真值相同）和标准差（0.1503 对 0.1493）。
5. T5：两点数据上，把精确后验当网络。GM-SDE 在 4 次和 50 次调用时，所有像素都落在数据点上，P[0] 的比例是 0.302 和 0.301（真值 0.3）。每个中间状态的边缘分布误差小于 0.014。GM-ODE（50 × 3，8 × 16）也都落在数据点上。对照：均值 Euler 4 次调用只有 90.8% 的像素落在数据点上。点模型路径逐步等于 DDPM-small。
6. T6：GM-ODE 子步的闭式重加权混合和网格上的数值贝叶斯一致，误差 7e-16。
7. T7：埋进去的模式在 unpatchify 后回到正确的像素、通道和分量。权重在 K 上和为 1。均值模式等于 Σ A μ。`gm_k = 0` 和改动前的模型（9711ff9）逐位相同，包括 bf16 autocast。
8. T8：初始化时 K 个均值不同，s_u = 1。t 接近 0 和 1 时损失和梯度都有限。s-MLP 的输入不传梯度。
9. T10：GM-ODE 在 n = 1 时等于混合均值上的精确 DDIM 步。`final_mean` 最后落在混合均值上。
10. 变异测试：5 个故意加的错误都被测试抓到。softmax 放在通道维上（T7 失败）；c1 和 c2 交换（T1、T3、T4、T5、T10 失败）；去掉 c3（T3、T5 失败）；s_x = s_u（T1、T3、T4、T6 失败）；GM-SDE 去掉桥的噪声（T5 失败）。
11. 原有的测试（能量头、隐式、plan A、AR）仍然全部通过。
12. 测试发现并修复了一个错误：抽分量时 Gumbel 噪声的符号写错，结果是 NaN，所有像素都选了第 0 个分量。

### 4.5 风险

1. 每个像素独立抽样。GM-SDE 在每一步和最后一步都给每个像素加独立的噪声。论文里去掉谱采样后 FID 从 6.96 变到 8.98。`gm_sde_final_mean` 用来看这一点。
2. RGB 只有 3 个通道。pi-Flow 的玩具测试里，C = 1 的逐元素分解颜色过饱和、纹理过平滑。
3. 损失的时间权重变了。点模型的 v 损失权重是 1/(1 − t)²，这里大约是 1/MSE(t)，上限由 transition loss 决定。K = 1 这一臂用来分开这个原因。
4. t 接近 1 时 s_x 很小，损失可能很大（T8 在 t = 1 − 6e-6 时损失约 7e7，梯度仍然有限）。GMFlow 用 transition loss 的下限 c3 和梯度裁剪来防止这个问题。我们的梯度裁剪是 1.0。
5. 墙钟时间没有测。fp32 的损失张量每张图 (8, 3, 256, 256)，比能量头大。FLOPs 只多 7%，墙钟时间可能多得更多。冒烟测试会测出来。
6. GPU 上没有跑过：编译、DDP、续训和预测都要等冒烟测试。

### 5.2 判定（两个算力点都要低 5%）

1. K = 8 对点模型：50 步 −0.6% 和 +0.7%，没过；8 步 −6.0% 和 −9.3%，通过。
2. K = 1 对点模型：50 步 +0.1% 和 −1.4%，没过；8 步 −3.8% 和 −6.1%，没过（C0/16 不到 5%）。
3. K = 8 对 K = 1：50 步 −0.7% 和 +2.2%，没过；8 步 −2.3% 和 −3.4%，没过。

### 5.3 8 步的优势从哪里来

1. K = 8 比点模型低 103.1 和 115.5。K = 1 已经低 64.8 和 75.7，即 63% 和 66%。混合自己多出的是剩下的约三分之一。
2. K = 1 的优势主要来自 GM-ODE 的子步，不是更好的均值。同样用官方 Euler 走均值，K = 1 只比点模型低 0.6% 和 2.2%；换成 GM-ODE 再低 3.3% 和 4.0%。子步在一次网络调用内部按学到的方差更新对干净图的估计；方差为 0 时子步等于精确一步（T10），所以点模型拿不到这部分。
3. 50 步时子步几乎没有用：K = 1 的 GM-ODE（1541.48 / 1074.47）还不如它的官方 Euler（1503.16 / 1056.40）。

### 5.4 其他读数

1. 学到的方差也训出了更好的均值：同一个官方 Euler（50 步），K = 1 比点模型低 2.4% 和 3.1%，K = 8 低 0.5% 和 0.5%。都不到 5%。
2. 每步从混合里抽样（GM-SDE）比沿均值走差，8 步时差得最多（K = 8：2150.77 对 1606.50）。它的 precision 最高（0.97），coverage 低。每个像素独立抽，和风险 1 一致。最后一步取均值（`gm_sde_final_mean`）在 C0/16 更差，所以问题不只在最后一步的噪声。
3. 官方 Euler 和精确一步只差 Euler 对 1 − t 的截断（不小于 0.05）。8 步的网格上没有 t > 0.95 的点，所以两者给出相同的样本（FD 都是 1709.604）。50 步时截断作用在 t = 0.96 和 0.98 两步，最后一步没有走到 x̂，留下一点噪声；精确一步的 FD 比它高 1.8% 和 4.8%。判定线把这部分给了点模型；GM-ODE 落在混合的结果上，拿不到它。
4. 梯度裁剪（评审 F4）：GMFlow 在预热期（0–4000 步）62.5%（K = 8）和 67.5%（K = 1）的记录步大于 1.0，之后 0.4%、1.5%，C0/16 以后 0%。点模型在 0–1000 步是 3/100，训练末尾 0/40（w1176）。所以两边的差别只在预热期，约占训练的 6%。
5. 每步时间：K = 8 由 ms 检查点算是 32.7 毫秒（点模型 30.05–32.93），FLOPs 多 7%、步数少 7%，训练的墙钟时间是 0.61 小时，点模型是 0.59 小时。

### 5.5 没有做的

一个种子。没有谱采样和二阶求解器。没有在 4 步以下评测。
