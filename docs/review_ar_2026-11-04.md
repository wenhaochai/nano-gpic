## 发现（按严重度排序）

### 1. C0/16 处 EMA 里初始权重的份额，AR 是基线的 2 倍（中，影响读法）

- 位置：`baselines/PixelGen/src/lightning_model_gpic.py:104`（EMA 从初始权重开始），`jobs/run_ar.sh:26`（评测步 26160 和 52320）。
- 问题：EMA 衰减是 0.9999，从初始化开始。第 s 步时初始权重的份额是 0.9999^s。
  - AR：26160 步时 7.3%，52320 步时 0.53%。
  - 基线：33408 步时 3.5%，66816 步时 0.13%。
  - 算力相同，所以 AR 的步数少，EMA 平均的窗口占训练的比例也大。初始权重给出 x̂ = 0（head 的输出层是零）。这一项对 AR 不利，在 C0/16 更明显。规则要求两点都低 5%，所以 C0/16 这个门槛对 AR 偏严。
- 修法（任选一个）：
  1. 在作业头部写明这个偏差，并只把 C0/8 作为必须通过的门槛。
  2. 两边在 C0/16 都另评一次原始权重（`--model.eval_original_model true`）。基线一次约 6 min。

### 2. AR 主干的残差流是 fp32，基线是 bf16（低）

- 位置：`baselines/PixelGen/src/models/transformer/AR_JiT.py:74`。
- 问题：`torch.cat([...], dim=1) + self.pos_embed` 是不原地的加法。bf16 加 fp32 参数，结果升为 fp32。基线用 `x += self.pos_embed`（`JiT_T2I.py:468`），原地加法保持 bf16。我在 CPU autocast 下用 hook 测过：AR 的 block0 输入输出是 float32，基线是 bfloat16。Linear 和 SDPA 仍然跑 bf16。但 norm、modulate、gate 加法和保存的激活是 fp32。
- 后果：数值和基线不同，可能对 AR 有利一点。训练步慢一些，激活显存多一些（d640 下只有几十 MB，不会 OOM）。这不是正确性问题。
- 修法：`x = torch.cat([...], dim=1) + self.pos_embed.to(x.dtype)`，与基线一致。改完要重新跑 `test_ar.py`。不改也可以，但要在 docs 里写明。

### 3. N > 1 时，`tf_rms` 不能按 docstring 那样读（低）

- 位置：`tools/ar/overfit_ar.py:12`（读法）和 `:83-91`（`teacher_forced`）。
- 问题：`tf_rms` 是抽出的 patch 到同一张图的距离。N = 256 时，前几个 patch 的分布本来就是 256 张图的混合：一个完美的模型也会抽到别的图的 patch。所以 tf_rms 里有合理的模式选择，不只是误差。tf_rms 可以高于 nn_rms，模型也可能没有误差累积。docstring 说“tf_rms 远低于 nn_rms 说明误差沿链增长”，这一方向的读法还成立。反方向不成立。
- 修法：只在 N = 1 时用 tf_rms 判断误差累积。或者把 tf_rms 改成按位置分段报告（例如第 128 个 patch 以后，那时图的身份已经确定）。这一项没有门槛，所以不阻塞。

### 4. AR 用了 region crop，基线 w1053 没有用（低）

- 位置：`jobs/train_ladder.sh:42`（默认 `GPIC_REGION_CROP=1`），`jobs/run_ar.sh:20`。
- 问题：w1053 跑在 18826587。这个 commit 不包含 eb4dd4c（region crop）。按 eb4dd4c 的说明，随机数相同，0.035% 的通道值不同，差别最多 2/255。影响可以忽略，但它是协议上的一个差别。
- 修法：在 `run_ar.sh` 里加 `export GPIC_REGION_CROP=0`，做到和基线完全一致。或者在作业头部写明这个差别。

### 5. 评测时间只是估计，主要不确定在 head 的每次调用开销（低）

- 位置：`AR_JiT.py:98-100`、`:108-110`；`jobs/eval_ar.sh:5`；`jobs/smoke_ar.sh:37`。
- 估计：每个 rank 处理 6250 张图，196 个 batch（每个 32 张）。
  - 主干：基线评测 203 s 做了 196 × 50 次前向，包括约 80 s 启动，所以 B = 32 时每次前向约 10-12 ms。AR 每个 batch 做 256 次前向，约 2.6-3.1 s。
  - head：每个 batch 调用 8192 次，M = 32 行，受 launch 开销限制。编译后、没有 CUDA graph 时，每次调用加上 draw_patch 的 eager 更新，约 0.25-0.4 ms，合 2-3.3 s。
  - 合计每个 batch 约 5-6.5 s，predict 约 16-21 min。加上启动和 FD 计算，约 20-25 min。
- 结论：`eval_ar.sh` 的 1 h 够用，smoke 的 2400 s 够用，`run_ar.sh` 的 2:50 也够用（训练约 35 min 加编译，再加两次评测约 45 min，合计约 1.5 h）。风险：如果 head 每次调用要 1 ms 以上，smoke 的评测会接近 2400 s。smoke 会测出真实时间。
- 可选的提速：AR 生成一张图要 256 × 34.47 + 32 × 9.87 ≈ 9.1 TFLOP，基线 50 步是 1.74 TFLOP，约为基线的 5.2 倍。用 KV cache 可降到约 0.35 TFLOP。head 循环可以用 CUDA graph（`mode="reduce-overhead"`）。这两项都不影响正确性，可以在 smoke 测出时间后再决定。

### 6. head 的 τ 嵌入在小 τ 处分辨率低（信息，不需要修）

- 位置：`src/models/layers/time_embed.py`（max_period = 10）。
- 事实：τ 在 [0, 1] 内，和官方调用方（`training_JiT.py` 传入 t ∈ [0, 1]）的范围相同。但嵌入几乎是线性的：τ = 0.01 到 τ = 0 的距离是 0.053，τ = 0.3 时是 1.58。docs 第 5 条说模式在很小的 τ 处就决定了，那么 head 要靠 MLP 放大这段很小的差别。官方模型也有这个性质。如果过拟合测试在 N = 256 时模式份额不对，可以先查这一点。

## 检查过并确认正确的项

1. 因果性和移位（问题 1）。
   - 第 i 个位置放 patch i−1（第 0 个位置放 BOS），加 pos_embed[i]，RoPE 也用位置 i。tril 包含对角线，所以 z_i 只看到 BOS 和 patch 0 … i−1。目标位置的位置编码就是 i，训练和采样一致。
   - mask 形状是 [B,1,N,N+T]，True = attend。文本部分来自 y_mask。每一行至少有一个 True（对角线），所以没有全部被屏蔽而出 NaN 的行。CFG 的空行保留第 0 个 token。
   - text refine 块只看 y。RMSNorm 和 LayerNorm 都按 token 计算。adaLN 的条件是每个样本一个常数 t 的嵌入，没有位置之间的混合。没有泄漏路径。
   - ar_sample 中 tokens[:, i:] 为零不改变任何东西：它们只进入第 i+1 及以后的位置。被屏蔽的 key 的偏置是 −inf，exp 后是精确的 0，bf16 下也是。
2. 编译路径（问题 2）。
   - 训练只走 q 不为空的路径，EMA 在 predict 只走 q 为空的路径（sample_every = 0）。CompileWarmup 在 DDP 前向上下文中跑 ARTrainer，T 的四个取值和基线相同。动态 T 只出现在 y_mask 的 expand 里，causal 的形状是固定的 N。
   - `causal` 是非持久 buffer：不在 state_dict 里（已检查），随 `.to(device)` 移动，`.to(torch.float32)` 不改变 bool 类型（已检查）。
   - deepcopy 后参数顺序相同（已检查）。`copy_params` 和 SimpleEMA 只用 `parameters()` 的顺序，不用 buffer。
   - `final_layer` 在父类 `__init__` 里初始化以后才删除。state_dict 里没有它的键（已检查）。仓库里没有用到 `final_layer` 的运行路径。`z_norm` 是没有参数的 LayerNorm。on_load_checkpoint 只查 pos_embed。strict 加载是关闭的，但 eval_ar 断言了 `head.out.weight`。
   - `_compiled_head` 放在 `__dict__` 里，不在 `_modules` 里（已检查），不会存进 checkpoint。EMA 的 deepcopy 在第一次采样以前，所以复制的是空状态。如果它在 deepcopy 前已经设置，副本也指向副本自己的 head（已检查）。`.to()` 原地改参数，所以 on_predict_start 的类型转换对它是安全的。

   - DDP：每个参数都有梯度（test_ar 第 3 项）。主干的 t_embedder 输入是 0，但仍在图里，有梯度张量。
3. 数学（问题 3）。
   - 损失：((x̂ − x)/clamp(1−τ, 0.05))²，与 JiTTrainer 的 (out − v_t)² 代数上相同，也是对所有值取平均。
   - draw_patch：从 τ = 0 的纯噪声开始，33 个点的均匀网格。前 31 步 1 − τ ≥ 0.0625 > t_eps，clamp 不起作用，分母不会爆。最后一步 q = x̂，等于 Euler 走到 τ = 1。
   - bf16：τ 的正弦嵌入在 fp32 里算，再进 bf16 的 MLP。z 是 fp32（layer_norm 在 autocast 下是 fp32）。x̂ 是 bf16，最后一步的舍入约 1 个 uint8 级别，和官方模型的输出相同。
