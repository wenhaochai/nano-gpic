## 检查过、确认正确的部分

1. 离散化（问题 1）。我读了附录 F.1.1 原文：R^DB(x₁→M) = η，R^DB(M→x₁) = ηt/(1−t)，揭开总速率是 (1+ηt)/(1−t)，t 是已揭开比例。代码里 t = 1 − cos(π/2·s/S)，变回概率 = η·Δt，单位一致。期望值也一致：每步多揭开的数量 ≈ ηΔt·K = ηtNΔt，和论文的 (N−K)·ηtΔt/(1−t) 相等。
2. 精确计数版本保持边缘分布。变回是每个 token 独立同分布的伯努利；抽哪些 token 是在遮挡集合里均匀取的，并且和 token 值无关。按可交换性，给定数量后，遮挡集合在同样大小的子集里均匀分布。每步结束时遮挡数量严格等于调度值 max(1, min(left−1, target))。
3. 概率 > 1：η·Δt > 1 时 `rand < p` 总为真，所有已知 token 都变回，结果正确。计划的 η ≤ 20 最大只到 0.49，不会出现这种情况。
4. 步内顺序：先变回、再前向。前向把变回的 token 当作遮挡，它可以在同一步被重新抽到。论文的 Euler 步里，变回的 token 在同一步不会被揭开。两者只差高阶项，而且精确计数已经决定了数量，所以这不是错误。最后一步 count = left，变回的 token 会被抽到，所有行结束时都没有遮挡 token。`left ≥ 1` 在每一步开头都成立，所以 count 不会是负数。
5. 一个 token 被抽两次时：`tokens[where]` 和 `context[where]` 都被覆盖，`unknown &= ~pick` 也正确。
6. η = 0 和 `_sample_random` 同分布（问题 2）。两者的遮挡数量逐步相同。每步从遮挡集合里均匀取一个子集，并且和 token 值无关，这在分布上等于开始时抽一个随机顺序。检查 17 在 vis 节点 CPU 上通过（全部 hostile 检查都通过；η = 20 时小模型的抽样数是 12.7 倍）。
7. 模型能回答的范围（问题 3）。命题 3.3 假设 p(x₁|x_t) 是精确的；模型不精确时，η 会改变结果，这正是这次要测的东西。前向看到的已知集合仍然是均匀随机子集，内容是模型自己的抽样，这和 η = 0 一样。已知比例在最后几步接近 1，这在 η = 0 的采样里同样出现。模型不会知道某个 token 曾经变回过。所以除了第 1 条（一步抽很多 token）以外，没有新的分布外输入。
8. 指标（问题 4）。`eval_eta.py:69-81` 和 `refine_ar.py` 的 `score()` 逐行相同：数据、cdist 的归一化、阈值 0.1、0.2、0.9 都一样，unfold 也一样。`head_draws_per_image` = 每批 draws/B 的平均值；2048 能被 32 整除，结果正确。有效图数按 idx 计算，和读法 3 一致。
9. 种子噪声。我用 w1135 的单样本数据算了 base 的有效图数：种子 11 和 12 分别是 114.8、114.7（权重 0）和 109.0、114.5（权重 1），相差不超过 5%，所以 20% 的门槛够用。distinct 在两个种子之间相差 0.031 和 0.004，0.05 的门槛偏紧但还可以，而且读法要求两份权重同时满足。near 和 covered 在种子之间相差 ≤ 0.01，所以读法 1 的 0.03 容差够用。
10. 作业（问题 6）。`flock … bash -c '…' $OUT/.next` 里，`$0` 是计数文件，自增是原子操作。`read -r w e` 能拆出 "random 20"。每个 worker 在 i ≥ 12 时退出。失败标记和 `fail=$?` 的逻辑正确。
11. 时长。head 每步只调用一次 `draw_patch`，所以 head 的串行调用次数是 64 × 32，不随 η 变化，只有每次调用的行数变多。按检查 11 的数，η = 20 时 head 计算量约 9.87 GFLOP × 10.8 × 2048 ≈ 0.2 PFLOP，在 H100 上不到 1 s。η = 0 的 110 s 主要花在 kernel 启动上。所以 η = 20 应该接近 110 s，远低于 1500 s 的单任务时限和 40 min 的作业时限。最坏情况按计算量线性放大（12.7 × 110 ≈ 1400 s），单任务仍在 1500 s 内，但 40 min 内跑不完 12 个任务。我认为这种情况不会出现（理由见上）。
12. 显存和 torch.compile。η = 20 的最后一步 head 约 32 × 126 ≈ 4000 行，宽度 1024，显存可以忽略。η = 0 时每步行数已经在变，compile 会切到动态形状；η > 0 只是形状取值更多。主干的输入形状固定，known 只改变值。
